# Next.js 15 + React 19 Monorepo Upgrade — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the whole Crivelo monorepo (root + `crivelo-web` + `crema-arena` + `@crivelo/ui` + `@crivelo/tokens`) from Next 14.2 / React 18.3 to Next 15 / React 19 in one atomic PR, including migrating crema-arena auth from next-auth v4 to Auth.js v5.

**Architecture:** One workspace, one `pnpm-lock.yaml`, bumped together. Dependency bump lands first; then mechanical codemods and per-app fixes over disjoint directories; the Auth.js v5 split-config migration is the highest-risk slice and runs as its own task after crema-arena's codemods. Gate is tsc + `turbo build` + dev smoke + Playwright screenshots; a committed e2e suite is a follow-up.

**Tech Stack:** Next 15, React 19, Auth.js v5 (`next-auth@5`), Turborepo, pnpm 11, Tailwind v4, Prisma 5, next-intl 4, motion 11, Playwright (MCP).

**Spec:** `docs/superpowers/specs/2026-06-12-nextjs-15-react-19-design.md`

`forwardRef<HTMLButtonElement, ButtonProps>((props, ref) => …)` becomes a plain function component taking `ref` as a normal prop. React 19 passes `ref` through. Example shape:

interface ButtonProps extends React.ComponentProps<"button"> {
  // ...existing variant props...
}
export function Button({ className, ref, ...props }: ButtonProps) {
  return <button ref={ref} className={cn(/* ...existing... */)} {...props} />;
}

Preserve the existing variant/`cn()` logic verbatim — only the ref plumbing changes. Drop the `forwardRef` import and any `Button.displayName = …` line.

## Task 6: crema-arena → Auth.js v5 (highest risk)

**Files:** Create `apps/crema-arena/auth.config.ts`, `apps/crema-arena/auth.ts`; Modify `lib/auth.ts`, `middleware.ts`, `app/api/auth/[...nextauth]/route.ts`, `types/next-auth.d.ts`, and ~28 `getServerSession` consumers.

**Before coding:** verify the current Auth.js v5 API against live docs — query context7 for `next-auth@5` (`/nextauthjs/next-auth`) "credentials split config middleware". v5 is beta; the split-config + `authorized` callback pattern below is the stable shape but confirm exports.

The split is required because `middleware.ts` runs on the edge and must NOT import `bcryptjs`/Prisma (pulled in by the Credentials provider). Edge-safe config lives in `auth.config.ts`; the Node-only provider lives in `auth.ts`.

- [ ] **Step 1: Create `apps/crema-arena/auth.config.ts` (edge-safe)**

```ts
import type { NextAuthConfig } from 'next-auth';

export const authConfig = {
  pages: {
    signIn: '/login',
  },
  session: { strategy: 'jwt' },
  callbacks: {
    async jwt({ token, user }) {
      if (user) {
        token.id = user.id;
        token.role = (user as { role?: string }).role;
      }
      return token;
    },
    async session({ session, token }) {
      if (session.user) {
        session.user.id = token.id as string;
        session.user.role = token.role as string;
      }
      return session;
    },
    // Edge-evaluated route protection used by middleware.
    authorized({ auth, request }) {
      const isAuthed = !!auth?.user;
      const { pathname } = request.nextUrl;
      if (pathname.startsWith('/dashboard')) return isAuthed;
      return true;
    },
  },
  providers: [], // providers added in auth.ts (Node runtime)
} satisfies NextAuthConfig;
```

- [ ] **Step 2: Create `apps/crema-arena/auth.ts` (full, Node runtime)**

```ts
import NextAuth from 'next-auth';
import Credentials from 'next-auth/providers/credentials';
import * as bcrypt from 'bcryptjs';
import { prisma } from '@/lib/prisma';
import { authConfig } from './auth.config';

export const { handlers, auth, signIn, signOut } = NextAuth({
  ...authConfig,
  providers: [
    Credentials({
      credentials: {
        email: { label: 'Email', type: 'email' },
        password: { label: 'Password', type: 'password' },
      },
      async authorize(credentials) {
        if (!credentials?.email || !credentials?.password) return null;
        const organizer = await prisma.organizer.findUnique({
          where: { email: credentials.email as string },
        });
        if (!organizer) return null;
        const isValid = await bcrypt.compare(
          credentials.password as string,
          organizer.password_hash
        );
        if (!isValid) return null;
        return {
          id: organizer.id,
          email: organizer.email,
          name: organizer.name,
          role: organizer.role,
        };
      },
    }),
  ],
});
```

- [ ] **Step 5: Rewrite `middleware.ts` with the `auth()` wrapper**

```ts
import { NextResponse } from 'next/server';
import NextAuth from 'next-auth';
import { authConfig } from './auth.config';

const { auth } = NextAuth(authConfig); // edge instance: no Credentials/bcrypt/prisma

export default auth((req) => {
  const { pathname } = req.nextUrl;
  const isAuthed = !!req.auth;

  if (pathname === '/') {
    if (isAuthed) {
      const url = req.nextUrl.clone();
      url.pathname = '/dashboard';
      return NextResponse.redirect(url);
    }
    return NextResponse.next();
  }
  if (pathname === '/login' && isAuthed) {
    const url = req.nextUrl.clone();
    url.pathname = '/dashboard';
    url.search = '';
    return NextResponse.redirect(url);
  }
  if (pathname.startsWith('/dashboard') && !isAuthed) {
    const url = req.nextUrl.clone();
    url.pathname = '/login';
    url.searchParams.set('callbackUrl', pathname);
    return NextResponse.redirect(url);
  }
  return NextResponse.next();
});

export const config = {
  matcher: ['/', '/login', '/dashboard/:path*'],
};
```
